# 项目设计与路线

## 目标与当前状态

Mirage · 浮城是面向数据中心的三维数字孪生个人项目。目标是把现实基础设施的空间、结构、连接与运行变化组织为可探索的数字世界，同时积累三维图形、领域建模、模型流程、实时数据与性能工程经验。

面向希望理解机房及设备运行的体验者、开发者和运维人员。项目独立设计，不限定于某个厂商、某种设备或特定管理系统；服务器与超节点按各自结构处理。

当前已完成机房 → 机柜 → 设备 → 部件的本地浏览链路，含镜头控制、结构展开复原、自动巡游和共享时钟的温度、功耗、运行状态与告警。八机柜包含 1U/2U 计算、接入交换机和双控存储，机型分别维护部件契约与可选配置；明确配置中的维护部件都有可选择几何。顶置交换机与后置 PDU 按安装约束布置，端口和 U 位做唯一性/冲突校验。趋势与时间控制按需打开，数据来源统一说明。运行方式、配置规模和限制集中见 [README](../README.md)。宏观入口、真实数据接入及完整网络/供电拓扑尚未实现。素材与许可集中见 [资产说明](../assets/README.md) 和 [许可范围](../LICENSE-ASSETS.md)。

## 体验范围

空间路径：**中国地图 → 园区 → 建筑 → 楼层 → 机房 → 机柜 → 设备 → 部件**。

| 方向 | 目标 |
| --- | --- |
| 空间浏览 | 园区分布、建筑分层、机房布局、墙体门窗、通道、制冷与配电设施；逐层进入、返回、旋转、缩放与聚焦 |
| 结构探索 | 机柜前后视角与开合、U 位安装、设备抽出/开盖、部件高亮、爆炸展开与复原 |
| 关系查看 | 网络端口与链路、供电与冷却关联、超节点成员；与物理位置联动 |
| 运行状态 | 功耗、温度、健康状态、指标趋势、告警发生与恢复；搜索和告警可直接定位 |
| 时间回放 | 场景暂停、重置、回看及重复运行，三维、拓扑和图表时间一致 |

中国地图使用前核实资源及适用要求，选材须符合项目的 CC0 规则；条件未满足时先使用明确标记的抽象园区分布入口，不把示意资源当作准确地图。

## 第一条完整链路

精做一个园区、一栋建筑、一个机房、一个机柜和一款可拆解服务器。先让空间浏览、设备选择和部件交互连续可用，再增加一个完整模拟场景：

**冷却能力变化 → 温度响应 → 告警触发 → 定位设备 → 查看趋势与关系 → 恢复回放。**

使用固定种子、有版本的场景与事件序列；其他对象用统一风格的原创简化资源。模拟规则和延迟明确记录，不宣称是精确热流体仿真或故障预测。超节点可作少量关系叠加或后续专题，不阻塞首条链路。

初期不连接实际管理系统，不执行远程开关机或配置变更。真实数据源从后续只读适配开始，单独记录验证范围。

## 下一轮体验设计（设计评审中）

本节记录下一轮设计基线。已增加独立的 `?review` 本地交互评审入口，复用现有模型、对象和确定性模拟，默认原型继续保留。评审稿用于验证信息架构与四个关键画面，不代表后续环境能力或正式统一工作区已经完成。名称与布局待实际评审确认；不因新增指标继续增加同级页签，也不在页面预留尚不可用的入口。

### 本轮可交互评审稿

底部“评审示例”载入机房浏览、温度分布、部件展开与运行回看四个固定画面；载入预设会重置对象、时间和展开姿态。日常图层切换、告警定位与时间回看各自独立，回看不重置相机与结构。评审默认暂停在第 60 秒并关闭环绕，便于稳定比较；不改变默认原型的播放与巡游策略。

| 画面 | 已可评审的结果 |
| --- | --- |
| 机房浏览 | 原始材质与少量状态标记；左侧定位、右侧对象读数和同口径小趋势，去除右侧重复对象列表 |
| 温度分布 | 在相同机房构图中切换已有温度着色；机房/机柜使用有效设备最高进风值，部件明确为模型表面温度 |
| 部件展开 | 2U 设备的 80% 展开预设；结构操作固定在场景下方，可跨图层使用，支持部件定位与复原 |
| 运行回看 | 第 90 秒的恢复过程；按需展开曲线与已发生事件，点击曲线或事件回看，三维与小趋势同步 |

当前评审入口按实际用途收敛为“空间 / 温度 / 功耗 / 告警”：空间查看对象的位置与结构，温度和功耗分别表达明确指标，告警在中间工作区提供场景与列表联动。右侧始终服务所选资源，不再承载告警浮窗；各入口共享选择与时间，不设置“数据”或“告警叠加”开关。环境、电力作为后续数据能力扩展后的领域名称再复核；空间容量与连接尚未实施，不显示空入口。

资源导航采用按层列表：机房列机柜与设施，机柜按 U 位从高到低列设备，设备内部按部件类别分组。名称同时显示类型、编号和位置；搜索支持中文类型、机柜、U 位和编号组合。单击只选中与预览，不移动相机或自动展开；明确点击“查看”后进入所在机柜，再查看设备内部。跨位置预览保持当前模型，切换实例前先让已抽出或展开的设备归位，并等待对应的场景就绪信号。

画面采用炭灰与暖白文字，低饱和青绿用于交互；状态同时使用颜色、形状和文字，指标使用连续色阶与单位。标签优先保留选择和异常对象，控制数量并避让碰撞。窄屏改为场景与概览纵向浏览，通过“资源导航”展开定位区域，部件选择保留独立下拉框。

评审稿尚无温度切片、气流、湿度/露点、空间容量、连接视图或曲线指标对比；开盖仍随现有展开编排进行，没有独立开盖动作。曲线只显示至当前时间；过期与缺失保留空缺，停机零值有效。真实设备接入、浏览器兼容性和性能基准未在本轮扩展。

### 场景、图层与操作

以“对象 × 数据图层 × 时间”组织体验。保留一个连续的三维场景、同一对象选择与共享时钟。结构拆解融入对象操作，不再和运行状态并列为观察模式；默认空间视图保留原始材质与必要状态标记。机柜开门、设备抽出、开盖、展开与复原随所选对象出现，切换指标后仍可操作。温度与功耗视图直接呈现各自指标。

主入口使用直接、可验证的名称，暂不以未实现的能力概括现有数据：

| 入口 | 回答的问题 | 当前范围 |
| --- | --- | --- |
| 空间 | 在哪里、是什么、内部如何组成？ | 机房与机柜浏览、资源预览、设备结构及对象操作 |
| 温度 | 哪里温度较高？ | 设备进风与部件模型温度，分别标记数据口径 |
| 功耗 | 当前用了多少电、占预算多少？ | 输入功耗、已知汇总与预算占比，不推断上游电源关系 |
| 告警 | 哪些对象异常、在哪里？ | 与温度、功耗同级的场景与告警列表，支持筛选、选中和定位 |

门开、维护、离线、数据过期分别表达，不统一算作故障。空间为默认入口，缺少的房间环境测点不沿用到部件；模型部件评估不进入设备告警计数。

### 布局与信息取舍

- 左侧承担资源查找与进入：一层一列表，搜索与类型筛选保持固定；选择、定位与查看内部各自明确，次级部件分组折叠。
- 中间以三维为主：图层选择与对象操作分组，图例跟随当前指标；标签按距离、选择和异常优先级显示，处理碰撞、遮挡与画面边界。
- 右侧服务所选对象：对象身份、当前图层关键值与小趋势在前，配置、数据质量和详细清单按需展开；避免重复左侧整棵树或铺满指标。
- 时间分析按需展开：从对象小趋势或事件进入，关闭后恢复场景空间。来源与模拟边界保留在统一说明和可查看的数据详情中。
- 桌面优先验证 1280×720 与 1440×900，窄屏验证 390×844；同时检查首次加载、长名称、滚动、展开面板与错误状态，不以隐藏溢出代替布局修复。

### 三维表现与数据含义

真实金属、塑料、PCB 与建筑材质形成底层质感；界面使用低亮度中性底色、清晰文字和少量强调色。运行状态色与指标色阶分开：正常、预警、严重通过颜色、形状和文字共同表达；高功耗或热图暖色不直接等于故障。具体色值先在真实场景中比较，再固定为统一设计变量。

| 维度 | 三维表现方向 | 约束 |
| --- | --- | --- |
| 温度 | 设备表面热图、可移动水平/垂直切片、热点定位 | 进风、排风与部件温度分开；测点、插值和模型推导有可查依据 |
| 湿度与露点 | 环境测点与局部区域，选中后查看关联读数 | 不给每个部件编造湿度；稀疏测点不直接冒充精确体积场 |
| 气流 | 有方向的流线与粒子，必要时叠加温度切片 | 先核对送回风、柜体前后及通道关系；示意模型不宣称 CFD 结果 |
| 电力 | 设备负载着色、柜侧刻度、选中对象的明确供电路径 | 区分 W 与 Wh、实测与预算；路径动画须有已定义端点 |
| 容量 | 空闲 U 位立体槽块、局部透视、安装范围与尺寸 | 占用、预留、不可用分别表达；连续空间依据真实 U 位配置计算 |
| 告警与事件 | 局部轮廓、定位线和短暂脉冲，点击进入事件 | 避免全场持续闪烁；发生、恢复、影响对象和推断关系分开 |

一个主着色图层可搭配少量辅助流线与所选对象定位标记，避免多个色场竞争。动效要表达方向、过程或注意力；减少动态效果偏好与低画质路径仍能读懂数据。雾效、泛光和粒子不能遮住模型、文字与选择反馈。

### 趋势与时间联动

对象小趋势跟随当前图层；展开后查看完整曲线、对比指标与事件。拖动时间时，三维读数、热图、气流模型状态、汇总和告警同步；相机与结构展开姿态保持当前操作。粒子位置是视觉动画，业务值由统一时间快照决定，不依赖上一帧积分才能回看。

当前为 120 秒确定性演示。新增环境输入须记录位置、单位、来源、质量、模型假设及时间响应；未来历史数据接入另行设计。回放、场景巡游和镜头环绕分别控制，不能把环绕动画当作指标变化。

### 开发顺序与验收

| 顺序 | 交付 | 验收重点 |
| --- | --- | --- |
| 1. 设计定稿 | 机房浏览、温度分布、部件展开、运行回看四个关键状态的交互稿 | 比较配色、层级、命名与信息量；无需解释也能找到对象、图层和结构操作，再确定入口名称 |
| 2. 统一工作区 | 融合运行状态与结构操作，整理导航和右侧概览 | 切换图层不丢失对象与时间，层级进退和复原连续，无重叠、穿透或焦点丢失 |
| 3. 环境与回放 | 温度切片、按布置建立的气流示意、对象趋势与事件联动 | 以冷却扰动、温升、告警与恢复演示完整过程；任意时间跳转结果一致，渲染降级可用 |
| 4. 空间容量与环境扩展 | U 位容量，具备数据定义后的湿度/露点 | 安装配置与容量一致；测点范围明确，缺失值不补成正常；复查不同层级可用入口 |
| 5. 关系与作品打磨 | 已定义的连接路径、设备细节、模型压缩与性能记录 | 关系端点可追溯，材质和标签可读；按实际设备与画面记录性能，整理展示路径 |

领域资料仅用于核对监测对象与物理含义：[ASHRAE 数据中心章节](https://handbook.ashrae.org/Handbooks/A23/SI/A23_Ch20/a23_ch20_si.aspx)、[Vertiv 环境监测](https://www.vertiv.com/en-emea/products/trusted-names/geist/vertiv-geist-environmental-monitoring/)。页面布局、视觉语言与场景资产独立设计；实际环境阈值须结合设备要求，不直接套用演示规则。

## 领域设计原则

| 信息 | 基本约束 |
| --- | --- |
| 空间 | 明确坐标、单位、父级与稳定 ID |
| 资产 | 型号定义、安装实例与实际部件分开；槽位显式映射到模型节点 |
| 关系 | 网络、供电、冷却与成员关系分别建模，端点明确；不硬塞进单一空间树 |
| 状态 | 指标附单位、来源、观测时间与质量；健康、通信与告警分别记录 |
| 时间 | 所有视图共享时钟；模拟、实时与历史回放模式明确 |

设备既有机柜位置，也可有超节点成员身份；CDU 可关联多个机柜。关联不依赖显示名、数组顺序或猜测槽位，未知映射保持未知。

渲染层读取领域状态，模型通过映射关联业务 ID；选择、告警、搜索与拓扑共用对象标识。镜头动画不修改业务状态。模型姿态、部件配置信息和可逆爆炸编排按 [资产流程](../assets/README.md) 维护。

指标、告警与回放消费同一模拟状态，不让面板各自随机。相同输入和模拟时间得到一致结果；测量、模拟、派生汇总与推断明确标记。后续多源采集需定义更新、迟到和过期数据的合并规则。

功耗按设备、机柜和设施的计量边界汇总，标记覆盖率，区分转换损耗、未计量与缺失。零值有效，缺失、过期和离线分别表达。告警有稳定身份、严重度、对象及发生/恢复时间，考虑持续和恢复条件。相关异常不直接称为已证实根因。

## 渲染与技术选择

远景使用点位和简化几何，进入对应层级再加载细节。重复设备复用模型与材质，退出和取消加载时释放资源或使用有界缓存。示意与精确模型区分展示。

先验证桌面浏览器体验，再确定设备规模、画质与其他端适配。性能结果附设备、浏览器、对象规模、采样方法和限制；有原型后再制定可测预算。

原型采用 React + TypeScript + Vite，Three.js 负责参数化场景、射线选择与镜头控制。领域对象与层级状态、渲染对象和模拟时钟分离，使用稳定 ID 映射；重复静态几何按材质合并，远景按机型使用实例化外观简模，当前查看设备切换对应详细结构，缓存上限为已定义的四种配置。场景定义与经维护者授权的原创贡献模型作为资产登记；GLB 部件通过显式节点契约关联 ID，加载失败有简化结构提示。使用局部面光源、细节接触阴影和程序化表面颗粒增强材质层次，保持标准渲染降级路径；阴影及后处理资源随引擎释放。渲染与交互代码为 Apache-2.0。地图方案、服务端与持久化尚未确定。

## 分阶段交付

| 阶段 | 交付目标 | 验收重点 |
| --- | --- | --- |
| 初始化（已完成） | 项目说明、资产与授权政策、隐私隔离及公开检查 | 公开文件无私有参考；许可全文完整；检查有效 |
| 原型验证 | 交互稿、最小应用、简化场景、模型与部件契约 | 可以启动，从机房进入机柜和设备；缺资源/失败有反馈 |
| 空间与结构 | 贯通宏观入口到部件的完整路径 | 返回与定位连贯；展开复原无累计误差；资源生命周期受控 |
| 状态与回放 | 一个有因果和恢复过程的模拟告警场景 | 重复运行一致；告警有依据；各视图时间相同 |
| 关系扩展 | 网络、供电、冷却、超节点及更多机型；只读数据适配 | 端点与映射清楚，双向定位一致，真实接入单独验证 |
| 作品交付 | 性能记录、公开演示、介绍视频与运行说明 | 他人可复现；资源许可可核对；成果与验证范围一致 |

当前优先按“下一轮体验设计”完成设计定稿与统一工作区，再逐步实现环境、时间与容量联动；设备细节、模型压缩和关系扩展随对应阶段推进。完整宏观路径仍需逐段建设。每完成一阶段，在此更新状态与验证入口；只有出现实际复杂度时再拆出专题文档。
