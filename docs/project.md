# 项目设计与路线

## 目标与当前状态

Mirage · 浮城是面向数据中心的三维数字孪生个人项目。目标是把现实基础设施的空间、结构、连接与运行变化组织为可探索的数字世界，同时积累三维图形、领域建模、模型流程、实时数据与性能工程经验。

面向希望理解机房及设备运行的体验者、开发者和运维人员。项目独立设计，不限定于某个厂商、某种设备或特定管理系统；服务器与超节点按各自结构处理。

当前已完成机房 → 机柜 → 设备 → 部件的本地浏览链路，含镜头控制、结构展开复原、自动巡游和共享时钟的温度、功耗、运行状态与告警。八机柜包含 1U/2U 计算、接入交换机和双控存储，交换机和 4U 存储已换用保留贴图的贡献外观，内部仍为独立配置示意；机型分别维护部件契约与可选配置；明确配置中的维护部件都有可选择几何。顶置交换机与后置 PDU 按安装约束布置，端口和 U 位做唯一性/冲突校验。趋势与时间控制按需打开，数据来源统一说明。运行方式、配置规模和限制集中见 [README](../README.md)。宏观入口、真实数据接入及完整网络/供电拓扑尚未实现。素材与许可集中见 [资产说明](../assets/README.md) 和 [许可范围](../LICENSE-ASSETS.md)。

## 体验范围

空间路径：**地球 / 园区分布 → 园区 → 建筑 → 楼层 → 机房 → 机柜 → 设备 → 部件**。

建设顺序由内向外：先精修一套完整机房，再形成单园区，最后扩展多园区与地球入口。地球展示已配置园区及可追溯汇总，不加载所有园区的设备细节；地域筛选属于分布入口，不作为必须经过的空间层级。

| 方向 | 目标 |
| --- | --- |
| 空间浏览 | 园区分布、建筑分层、机房布局、墙体门窗、通道、制冷与配电设施；逐层进入、返回、旋转、缩放与聚焦 |
| 结构探索 | 机柜前后视角与开合、U 位安装、设备抽出/开盖、部件高亮、爆炸展开与复原 |
| 关系查看 | 网络端口与链路、供电与冷却关联、超节点成员；与物理位置联动 |
| 运行状态 | 功耗、温度、健康状态、指标趋势、告警发生与恢复；搜索和告警可直接定位 |
| 时间回放 | 场景暂停、重置、回看及重复运行，三维、拓扑和图表时间一致 |

地球、地图、地形与园区坐标资源使用前核实来源、许可与适用要求，遵循现有资产规则。没有可用数据时使用明确标记的示意位置，不把虚构园区当作真实地点。

## 第一条完整链路

以当前机房为样板，精做建筑空间、机柜、四种已有设备及维护部件，再向一栋建筑和一个园区扩展。每个层级都要有完整的进入、操作、数据表达与返回体验。当前贯通的模拟场景继续作为设计验收主线：

**冷却能力变化 → 温度响应 → 告警触发 → 定位设备 → 查看趋势与关系 → 恢复回放。**

使用固定种子、有版本的场景与事件序列；其他对象用统一风格的原创简化资源。模拟规则和延迟明确记录，不宣称是精确热流体仿真或故障预测。超节点可作少量关系叠加或后续专题，不阻塞首条链路。

初期不连接实际管理系统，不执行远程开关机或配置变更。真实数据源从后续只读适配开始，单独记录验证范围。

## 下一轮体验设计（设计评审中）

本节记录已落地的统一工作区与后续设计基线。默认入口已整合资源定位、数据图层、对象操作、时间分析和自动巡游；`?review` 使用同一组件提供固定暂停的评审状态，旧界面移至 `?prototype` 供对照。后续环境能力继续按本节逐步实施，名称与布局通过实际画面打磨；不因新增指标继续增加同级页签，也不在页面预留尚不可用的入口。

### 本轮设计收敛与待实施重点

本轮决定先完成场景表达与工作区精修，再推进容量与更大尺度。技术链路可用不等于视觉验收完成。以下为待实施设计，不表示当前页面已经达到目标。

首批精修已落地：资源导航收起按钮位于栏内标题右侧，收起后从场景工具栏左端的“资源”入口展开；页头只保留空间路径。展开时聚焦搜索，关闭或按 Esc 后焦点返回入口，搜索条件与对象选择保留；进入对象保留桌面导航选择；温度图例压缩至场景下沿。气流使用具有实体宽度的送风线、分段回风线与更清晰的方向箭头，保留暂停、过期静态与真实遮挡。新增门禁读卡器、两处烟感与两处墙柱环境探头，仅为结构布置示意，未接入监测或独立选择。端点就地标签、建筑材质与遮挡调整、设施关系及其余关键画面仍待精修。

**规模先保持，完整度先提升。** 当前 14×12 米、8 柜、84 台设备作为样板与回归基线。暂不通过加柜、复制设备或扩大空地制造规模感；只有新增系统、合理通道或服务空间确实需要时才调整尺寸。扩展前先验证不同朝向、不同机房配置和对象 ID 的复用，避免把当前同向双排布置写死成通用机房。

**气流必须可辨认。** 原细虚线的可见性已作首轮增强，端点含义仍主要依赖角落文字。后续收敛一条完整代表路径：制冷单元送出 → 地板送风位置 → 目标设备进风 → 柜后回风假设；用具有可见宽度的流带、间隔明确的方向标与短脉冲表达流向。送风与回风通过色彩、实虚和端点共同区分；暂停时仍能读出方向。只在端点附近给出“送风 / 进风 / 回风假设”和当前有效读数，选中后强调该支路，其余减弱。先核对实际渲染后的可读性，再决定室内总览是否同时展示两条路径。不得用整场泛光、铺满粒子或关闭所有深度遮挡补救可见性，也不把线宽或运动速度解释成未定义的风量。

**场景承载位置与数值，面板承载比较与解释。** 温度放在切片、测点及对象附近；功耗放在柜侧标尺和已定义供电支路；容量放在空闲 U 位；告警放在异常对象和独立告警入口。关键数字必须有单位、对象和数据质量，精确值随选中显现；三维负责发现，曲线负责时间比较，列表负责检索。取消重复 KPI、长标题、常驻说明和重复操作；来源、模型边界与配置折叠查看。信息移入场景后仍要有键盘可访问的对象详情，不能只依赖悬停、颜色或动画。

**视觉目标是精致的基础设施作品。** 保留金属、PCB、线缆与建筑的材质层次，降低地板重复纹理、墙体和桥架对主体的争抢；根据视角处理遮挡，选中与展开对象形成清晰视觉中心。科技感来自可解释的流向、空间刻度、切片和时间变化。数据颜色与状态颜色保持独立，不让所有正常设备发光，也不以满屏标签增加信息感。

### 样板机房与园区设施范围（待实施）

下表是演示范围与建模优先级，不是实际工程设计或所有数据中心的强制配置。先明确采用的冷却、供电方案，再建对应对象；风冷与液冷等不同方案不为凑数量混放。

| 系统 | 当前基础 | 样板机房下一步 | 园区阶段及边界 |

设施采用三级精度：背景建筑只需可信外观；可选择设施具备身份、位置、端点与状态；需要维护展示的设备才有内部部件与可逆操作。新增资产先核对许可、模型契约与所需数据，不把模型存在视为遥测已经存在。

### 当前可交互画面

**独立布局提案（`?design`，待视觉定稿）**：右上“画面评审”提供机房浏览、设备内部、告警排查和时间分析四个固定画面，复用现有三维引擎、对象操作和第 60 秒暂停的模拟状态。资源行统一为名称、类型/位置、状态符号和横向操作区，文字按钮不再形成第二块悬浮背景，定位与进入使用同一尺寸；跨范围搜索保留机柜与 U 位，部件子件按需展开。单击名称预览，定位聚焦，进入下一级，三者保持明确区分。视图切换与视角工具位于场景上方，视角、聚焦与显示设置合为一组，按场景实际宽度换至第二行；对象操作靠近场景下沿，投影标签避让这些控件。温度切片图例独立排布方向、色阶、位置与有效范围，滑杆可直接操作。右侧详情收紧身份与异常摘要，将温度、功耗并列，小趋势及说明按需查看。

告警直接筛选当前层级资源，通过“仅看告警”筛选切换异常与全部资源，并保留空间异常标记；进入机柜后继续列该柜异常设备，部件模型评估不当作独立告警。模拟播放与明确的“分析”入口收入页头，完整曲线、共享时间及已发生事件使用同一个右侧分析栏，替换普通详情，不再叠加底部告警表与时间条；分析栏顶端可直接返回详情，标明播放状态与场景同步。Esc 优先清除搜索、关闭菜单/分析/详情，再返回空间上一级。中等宽度下资源与详情分时占位，选择或定位后自动收起资源，避免三栏同时挤压模型；手机宽度下详情和分析接在场景后方，温度卡片完整容纳控制与说明。当前已验证资源进入、子件展开、告警范围筛选、回看保留姿态及桌面/窄屏布局；不代表视觉定稿、移动触控完整验收或性能基准测试。设备模型、气流与设施细节仍沿用现状，后续按下述计划精修。

以下描述默认工作区与 `?review` 的既有实现，用于和独立提案比较；提案尚未替换它们。

工作区组合已完成一轮调整：资源入口与视图页签采用独立的尺寸和间距；资源按 A/B 排及设施分组，紧凑行保留类型、编号、状态，机柜内部保留 U 位，跨范围搜索显示完整位置。每行右侧为独立操作区，按对象和当前层级提供定位、进入；单击名称仍只预览，移除左侧底部重复的选中对象操作块。告警页签不再附数量，数量及级别筛选集中在告警列表，告警场景不显示无关的运行 KPI。结构操作、视角、聚焦与画面设置在场景下沿实际占一行，窄屏自动换行；展开进度按需打开。底部列表和曲线共用同一区域，“当前告警 / 曲线与事件”互斥切换并可收起，模拟时间条固定在桌面底部。右侧入口按对象显示“机房概览 / 所选详情”，展开后形成独立栏位，不覆盖场景、操作或分析；详情标题保持可见，切换对象回到顶部。窄屏依次排列场景、时间、底部内容及详情，不叠浮层。巡游控制收入“演示”菜单，菜单在巡游中显示状态；模拟标识位于桌面时间条。

本轮验证重点为资源预览与直接进入、导航开关、图层与告警筛选、分析回看、详情显隐及桌面/窄屏碰撞；不据此宣称全部视觉设计已定稿。模型、设施与气流端点标签仍按后续计划打磨。

顶部“演示”菜单载入机房浏览、温度分布、部件展开与运行回看四个固定画面；载入预设会重置对象、时间、展开姿态与切片设置。日常图层切换、告警定位与时间回看各自独立，回看不重置相机与结构。默认入口从第 60 秒开始播放和巡游，减少动态效果偏好下保持自由探索；`?review` 暂停在第 60 秒并关闭环绕，便于稳定比较。巡游等待镜头和结构就绪才计时，手动操作接管；从其他机型开始巡游时先让旧实例归位，再切换至演示服务器。

| 画面 | 已可评审的结果 |
| --- | --- |
| 机房浏览 | 原始材质与少量状态标记；左侧定位、右侧对象读数和同口径小趋势，去除右侧重复对象列表 |
| 温度分布 | 机房支持水平/垂直进风切片与少量气流代表路径，共用时间与对象；机柜保留 U 位色条，部件明确为模型表面温度 |

| 运行回看 | 第 90 秒的恢复过程；上下对齐的温度与功耗双曲线，共享游标、场景时间和事件；支持点击或方向键回看 |

统一工作区按实际用途收敛为“总览 / 温度 / 功耗 / 告警”：总览保留对象原材质与状态，支持位置和结构浏览，温度和功耗分别表达明确指标，告警在中间工作区提供场景与列表联动。机房总览默认收起右侧详情，将运行设备数、已知输入功耗与有效覆盖融入场景；选择资源后按需展示精简详情与小趋势，不再固定占用整列宽度；各入口共享选择与时间，不设置“数据”或“告警叠加”开关。环境、电力作为后续数据能力扩展后的领域名称再复核；空间容量与连接尚未实施，不显示空入口。

资源导航采用按层列表：机房列机柜与设施，机柜按 U 位从高到低列设备，设备内部按部件类别分组。名称同时显示类型、编号和位置；搜索支持中文类型、机柜、U 位和编号组合。单击只选中与预览，不移动相机或自动展开；点击行右侧“进入”后进入所在机柜，再查看设备内部；“定位”聚焦可见资源，部件使用定位操作。跨位置预览保持当前模型，切换实例前先让已抽出或展开的设备归位，并等待对应的场景就绪信号。

温度在机房和机柜层级按实际 U 位显示逐设备色条；功耗用机柜旁的预算标尺与 W/kW 标签表达，不把整台模型涂成指标色。设备内部保留已有部件表面着色，并增加跟随展开几何的部件读数。指标缺失与零值分开，数据变化与共享时间同步。

机房温度视图已直接接入水平切片，图例提供 0.20–2.10 米高度调节，并显示本层有效输入数与估计范围。模型 `intake-local-idw-v1` 只使用当前有效设备进风读数；代表位置按设备 U 位中心、机柜正面前方 0.08 米假设。按 X/Y/Z 方向 1/0.55/1 米的椭球邻域作紧支撑反距离加权，权重为 `(1-d²)²/d²`，仅估计机柜正面区域；最近代表位置无效时留空，不以邻居补成正常。结果与共享时钟同步，调高度和回看不触发镜头或结构变化。机柜标签显示“本层约”估计，右侧与机房汇总继续显示设备读数及最高值；它们与环境实测、排风及 CFD 结果分开。参数集中在场景 JSON，算法与渲染由独立代码实现。

同一图例已支持切换垂直方向，按场景明确登记的 A/B 排及真实机柜正面位置取样，范围为 0.20–2.10 米高度、距柜面 0.08–0.90 米；下限避开柜门与把手，防止表面重合。只使用所选排的输入，保留无效区域空白。垂直标签显示沿切面高度采样的最高估计，并注明“切面最高约”，不沿用水平“本层”口径。方向、机柜排、位置和回看保持当前对象、镜头与结构；图层切换保留各方向设置，载入演示预设恢复水平初始设置。切片保留真实深度遮挡，可旋转观察；它不代表气流或房间环境实测。

气流示意 `representative-airflow-v1` 已融入机房温度视图。当前两排机柜同向朝 +Z，不称为封闭冷热通道；四种设备模型均明确登记“假设前进后出”。路径绑定已配置的冷却关系：低位沿空闲侧通道送至柜前地板格栅、升至设备 U 位后穿柜，再在 2.65 米高度示意回风。制冷单元出入口为逻辑端点，未识别真实风口；路径不表示实测风速、排风温度或 CFD 结果。参数、方向假设与色彩集中在场景 JSON。

水平机房画面只取每排首柜中最接近 1.2 米的已配置运行服务器作代表，标签标明机柜和设备；选中机柜/设备后仅显示其对应路径，部件沿用所属设备。垂直切片仅显示当前排，所选对象在排外时保持选择并使用当前排代表路径。送风蓝、穿柜浅青、回风灰米色分别表示路径环节，不使用告警色；送风线明暗随冷却输入变化，不推算风量或风速。粒子使用共享时钟的绝对时间，暂停、回看与倍速不依赖上一帧积分；停机、维护、离线、过期或缺失对象保留灰色静态方向，减少动态效果偏好下只留箭头。设备内部和镜头转场不显示机房流线，避免与结构探索重叠。

画面采用炭灰与暖白文字，低饱和青绿用于交互；状态同时使用颜色、形状和文字，指标使用连续色阶与单位。标签优先保留选择和异常对象，控制数量并避让碰撞。窄屏改为场景与概览纵向浏览，通过“资源导航”展开定位区域，部件选择保留独立下拉框。

1U/2U 服务器已支持独立开盖：只移开上盖，其他部件保持装配；展开前自动取盖，合盖前先复原部件。开盖状态随图层、回看和重播保留，返回机柜前先合盖，切换设备不继承开盖姿态。交换机与存储仍使用外观与内部配置示意切换。

时间分析已支持同一对象的温度/功耗对照：两条曲线分别标明单位与读数口径，悬停同时查看历史值，点击曲线、事件或使用方向键回看，开盖和展开姿态保持不变。公共冷却输入在当前范围合并显示，设备告警分别保留；数据过期后仍保留此前已知事件。

当前已有机房水平/垂直进风温度切片与气流示意；湿度/露点、空间容量和连接视图尚未实施。曲线与量程仅使用当前时刻之前的观测；过期与缺失保留空缺，停机零值有效。真实设备接入、浏览器兼容性和性能基准未在本轮扩展。

### 场景、图层与操作

以“对象 × 数据图层 × 时间”组织体验。保留一个连续的三维场景、同一对象选择与共享时钟。结构拆解融入对象操作，不再和运行状态并列为观察模式；默认总览视图保留原始材质与必要状态标记。机柜开门、设备抽出、开盖、展开与复原随所选对象出现，切换指标后仍可操作。温度与功耗视图直接呈现各自指标。

主入口使用直接、可验证的名称，暂不以未实现的能力概括现有数据：

| 入口 | 回答的问题 | 当前范围 |
| --- | --- | --- |
| 总览 | 当前有什么、在哪里、内部如何组成？ | 机房与机柜浏览、资源预览、设备结构及对象操作 |
| 温度 | 哪里温度较高？ | 设备进风与部件模型温度，分别标记数据口径 |
| 功耗 | 当前用了多少电、占预算多少？ | 输入功耗、已知汇总与预算占比，不推断上游电源关系 |
| 告警 | 哪些对象异常、在哪里？ | 与温度、功耗同级的场景与告警列表，支持筛选、选中和定位 |

门开、维护、离线、数据过期分别表达，不统一算作故障。总览为默认入口，缺少的房间环境测点不沿用到部件；模型部件评估不进入设备告警计数。

### 布局与信息取舍

- 左侧承担资源查找与进入：一层一列表，搜索与类型筛选保持固定；选择、定位与查看内部各自明确，次级部件分组折叠。
- 中间以三维为主：图层选择与对象操作分组，图例跟随当前指标；标签按距离、选择和异常优先级显示，处理碰撞、遮挡与画面边界。
- 右侧为可收起的所选对象详情：对象身份、当前图层关键值与小趋势在前；配置和数据质量按需展开。默认机房读数进入场景，减少重复内容和常驻面板。
- 时间分析按需展开：从对象小趋势或事件进入，关闭后恢复场景空间。来源与模拟边界保留在统一说明和可查看的数据详情中。
- 桌面优先验证 1280×720 与 1440×900，窄屏验证 390×844；同时检查首次加载、长名称、滚动、展开面板与错误状态，不以隐藏溢出代替布局修复。

### 三维表现与数据含义

真实金属、塑料、PCB 与建筑材质形成底层质感；界面使用低亮度中性底色、清晰文字和少量强调色。运行状态色与指标色阶分开：正常、预警、严重通过颜色、形状和文字共同表达；高功耗或热图暖色不直接等于故障。具体色值先在真实场景中比较，再固定为统一设计变量。

| 维度 | 三维表现方向 | 约束 |
| --- | --- | --- |
| 温度 | 设备表面热图、可移动水平/垂直切片、热点定位 | 进风、排风与部件温度分开；测点、插值和模型推导有可查依据 |
| 湿度与露点 | 环境测点与局部区域，选中后查看关联读数 | 不给每个部件编造湿度；稀疏测点不直接冒充精确体积场 |
| 气流 | 有方向的流线与粒子，必要时叠加温度切片 | 先核对送回风、柜体前后及通道关系；示意模型不宣称 CFD 结果 |
| 电力 | 设备负载着色、柜侧刻度、选中对象的明确供电路径 | 区分 W 与 Wh、实测与预算；路径动画须有已定义端点 |
| 容量 | 空闲 U 位立体槽块、局部透视、安装范围与尺寸 | 占用、预留、不可用分别表达；连续空间依据真实 U 位配置计算 |
| 告警与事件 | 局部轮廓、定位线和短暂脉冲，点击进入事件 | 避免全场持续闪烁；发生、恢复、影响对象和推断关系分开 |

一个主着色图层可搭配少量辅助流线与所选对象定位标记，避免多个色场竞争。动效要表达方向、过程或注意力；减少动态效果偏好与低画质路径仍能读懂数据。雾效、泛光和粒子不能遮住模型、文字与选择反馈。

### 趋势与时间联动

对象小趋势跟随当前图层；展开后查看完整曲线、对比指标与事件。拖动时间时，三维读数、热图、气流模型状态、汇总和告警同步；相机与结构展开姿态保持当前操作。粒子位置是视觉动画，业务值由统一时间快照决定，不依赖上一帧积分才能回看。

当前为 120 秒确定性演示。新增环境输入须记录位置、单位、来源、质量、模型假设及时间响应；未来历史数据接入另行设计。回放、场景巡游和镜头环绕分别控制，不能把环绕动画当作指标变化。

### 开发顺序与验收

| 顺序 | 交付 | 验收重点 |
| --- | --- | --- |
| 1. 场景与工作区精修（当前优先） | 气流可读性、四个关键画面、模型质感、导航与控件组合 | 完成上表交互与截图验收；数据能就地读懂，减少重复面板；既有链路无回退 |
| 2. 样板机房系统补全 | 按设施范围逐项明确空间、冷却、供电、布线与数据端点；打磨已有设备内部 | 模型、安装与关系一致；设施位置合理；没有数据的对象不伪装成监测对象 |
| 3. 容量与环境扩展 | U 位占用/预留/不可用、连续可用空间；具备测点定义后的湿度/露点 | 从安装配置计算；稀疏测点有边界；当前视图自然承载数据，再复核入口命名 |
| 4. 单建筑与单园区 | 建筑—楼层—机房，辅助区域与室外系统；复用样板契约扩展配置 | 稳定 ID、坐标转换、跨层定位、范围汇总与往返状态一致；按层加载通过验证 |
| 5. 多园区与地球入口 | 地球上展示已配置园区，逐级进入同一工作区；性能、资产压缩与作品展示 | 地理资源合规；宏观不加载全部细模；汇总不重复计量；记录真实设备上的性能与限制 |

领域资料仅用于核对监测对象与物理含义：[ASHRAE 数据中心章节](https://handbook.ashrae.org/Handbooks/A23/SI/A23_Ch20/a23_ch20_si.aspx)、[Vertiv 环境监测](https://www.vertiv.com/en-emea/products/trusted-names/geist/vertiv-geist-environmental-monitoring/)。页面布局、视觉语言与场景资产独立设计；实际环境阈值须结合设备要求，不直接套用演示规则。

## 领域设计原则

| 信息 | 基本约束 |
| --- | --- |
| 空间 | 明确坐标、单位、父级与稳定 ID |
| 资产 | 型号定义、安装实例与实际部件分开；槽位显式映射到模型节点 |
| 关系 | 网络、供电、冷却与成员关系分别建模，端点明确；不硬塞进单一空间树 |
| 状态 | 指标附单位、来源、观测时间与质量；健康、通信与告警分别记录 |
| 时间 | 所有视图共享时钟；模拟、实时与历史回放模式明确 |

设备既有机柜位置，也可有超节点成员身份；CDU 可关联多个机柜。关联不依赖显示名、数组顺序或猜测槽位，未知映射保持未知。

渲染层读取领域状态，模型通过映射关联业务 ID；选择、告警、搜索与拓扑共用对象标识。镜头动画不修改业务状态。模型姿态、部件配置信息和可逆爆炸编排按 [资产流程](../assets/README.md) 维护。

指标、告警与回放消费同一模拟状态，不让面板各自随机。相同输入和模拟时间得到一致结果；测量、模拟、派生汇总与推断明确标记。后续多源采集需定义更新、迟到和过期数据的合并规则。

功耗按设备、机柜和设施的计量边界汇总，标记覆盖率，区分转换损耗、未计量与缺失。零值有效，缺失、过期和离线分别表达。告警有稳定身份、严重度、对象及发生/恢复时间，考虑持续和恢复条件。相关异常不直接称为已证实根因。

## 渲染与技术选择

远景使用点位和简化几何，进入对应层级再加载细节。重复设备复用模型与材质，退出和取消加载时释放资源或使用有界缓存。示意与精确模型区分展示。

先验证桌面浏览器体验，再确定设备规模、画质与其他端适配。性能结果附设备、浏览器、对象规模、采样方法和限制；有原型后再制定可测预算。

原型采用 React + TypeScript + Vite，Three.js 负责参数化场景、射线选择与镜头控制。领域对象与层级状态、渲染对象和模拟时钟分离，使用稳定 ID 映射；重复静态几何按材质合并，远景按机型使用实例化外观简模，当前查看设备切换对应详细结构，缓存上限为已定义的四种配置。场景定义与经维护者授权的原创贡献模型作为资产登记；GLB 部件通过显式节点契约关联 ID，加载失败有简化结构提示。使用局部面光源、细节接触阴影和程序化表面颗粒增强材质层次，保持标准渲染降级路径；阴影及后处理资源随引擎释放。渲染与交互代码为 Apache-2.0。地图方案、服务端与持久化尚未确定。

## 阶段状态与推进规则

机房到部件、统一工作区和环境回放的基础链路已经实现；气流可读性、整体视觉与模块组合尚需精修。当前优先执行上文“场景与工作区精修”，容量暂排在其后；单园区与地球入口仍为计划。阶段交付与验收集中维护在“开发顺序与验收”，避免多套路线互相冲突。

每完成一项明确任务，更新当前状态与限制，提供对应页面证据并本地提交。扩大规模前验证配置可复用与资源生命周期；性能结果须附设备、浏览器、对象规模、方法与限制。真实数据接入、公开部署与发布另按实际授权推进。
