## 项目介绍

浮城（Mirage）是一个面向数据中心的三维数字孪生个人项目。它规划以地球上的园区分布为入口，从园区、建筑与机房逐层深入机柜、设备和内部部件，将宏观的空间布局与微观的设备结构连接起来，构建一个可以浏览、探索和交互的数字世界。

项目规划通过机柜开合、设备抽出、结构拆解与爆炸图呈现设备形态，并结合网络、供电及冷却关系，关联功耗、温度、健康状态和告警等运行数据。借助空间定位与历史回放，让设备在哪里、如何连接、正在发生什么，都能在同一个场景中被观察和理解。

> 当前已实现本地的机房 → 机柜 → 设备 → 部件链路，包含双排八机柜、84 台混合设备及后置 PDU。四种机型有独立的维护部件清单、可逆展开、选择与聚焦；温度、功耗、告警和态势共用一个可回放的确定性场景。宏观地图、完整关系网络与真机接入仍为建设目标，未部署在线演示。

## 探索路径

**地球 / 园区分布 → 园区 → 建筑 → 楼层 → 机房 → 机柜 → 设备 → 部件**

空间浏览、设备结构、网络/供电/冷却关系与运行数据相互关联。超节点作为可选的设备成员关系与专题视图，成员保留各自的物理位置。

第一版先贯通：**一个机房、八个混合机柜、四种设备配置、一个可重复播放的告警场景**。模拟数据明确标记，所有视图共享对象标识与时间线。先精修这套样板的场景表达、布局与设施关系，再扩展单园区，最后建设多园区与地球入口。详细边界与交付步骤见 [项目设计与路线](docs/project.md)。

## 当前运行与检查

原型使用 React、TypeScript、Vite 与 Three.js。建议 Node.js 24，最低 22.12；首次安装依赖后启动本地开发服务：

```bash
npm install
npm run dev
```

打开终端显示的本地地址，即可进入统一三维工作区。主入口为“总览 / 温度 / 功耗 / 告警”，对象操作和时间分析共用同一场景；默认从第 60 秒开始播放并自动巡游。顶部“演示”菜单可暂停或继续巡游，操作场景、查找资源或切换图层会接管为自由探索；模拟播放与巡游分别控制。减少动态效果偏好下默认自由探索，后台暂停画面、巡游与数据推进。

底部时间条可播放、暂停或回看；“曲线与事件”展开时间分析，同时对照温度和功耗，点击曲线、事件或使用方向键回看，开盖和展开姿态保持不变。对象详情的小趋势按当前图层显示，完整分析打开后收起重复小趋势。告警列表与曲线共用底部区域，可切换或收起；桌面详情独立占右栏，场景操作固定在场景下沿，时间条保持在底部。数据来源集中在顶部“关于”。

“演示”菜单可载入机房浏览、温度分布、部件展开与运行回看示例，载入时重置对象、时间、结构与切片设置并停止巡游。`?review` 复用同一工作区，固定暂停在第 60 秒用于评审；`?prototype` 保留旧界面供对照。范围和后续计划见 [工作区体验设计](docs/project.md#下一轮体验设计设计评审中)。

新的布局提案从 `?design` 独立进入，右上“画面评审”切换机房浏览、设备内部、告警排查和时间分析四个可交互画面。告警筛选复用左侧资源目录，时间控制收入页头，完整曲线替换右侧详情；没有常驻底部列表或时间条。此入口用于设计比较，尚未替换默认工作区，模型与数据边界沿用现有实现。

拖动旋转、滚轮缩放、单击选择、双击进入；面包屑与 Esc 返回，F 聚焦。机柜门与服务器导轨按顺序开合、抽出和归位；固定安装的交换机不使用抽屉动作，进入时切换到结构展示台。1U/2U 服务器可单独打开上盖观察装配内部，再展开或复原部件；合上上盖会先复原部件，返回机柜前自动合盖。手动开盖后“复原部件”保留开盖状态，图层和时间切换也保留结构姿态。设备支持独立部件选择。资源栏标题右侧可收起导航，从场景工具栏左端“资源”重新展开；搜索条件保留，Esc 关闭后焦点返回入口。左侧按柜排与设施分组，行右侧提供定位与进入，不再使用底部选中卡片；机柜内部保留 U 位，设备内部按实际机型显示模块与子件，支持搜索；小屏通过对象详情的下拉框选择。细节阴影与镜头环绕集中在“画面”。需要支持 WebGL 2 的桌面浏览器，小屏上下浏览场景与详情。

14×12 米机房有六个计算柜与两个计算/存储混合柜；交换机位于 U39 和 U41，4U 存储位于后排两柜的 U25–28 与 U35–38，PDU 装在后侧通道，不占标准 U 位。另有门禁读卡器、两处烟感和两处墙柱环境探头的布置示意，尚未接入数据或独立选择。所有设备安装范围均做冲突检查。配置集中在 `assets/public/scenes/room-01.json`：

| 配置 | 数量 | 结构 |
| --- | --- | --- |
| M1 · 1U 计算 | 20 | 双处理器、8 条内存、4 个双转子风扇模组、4 块 SAS SSD、网卡、存储控制卡、单转接架与双电源 |
| M2 · 2U 计算 | 44 | 双处理器、16 条内存、4 个风扇、8 块 SAS SSD、网卡、存储控制卡、双转接架与双电源 |
| N1 · 1U 接入 | 16 | 48 个 25G SFP28、6 个 100G QSFP28、交换芯片、控制板、4 个风扇与双电源 |
| S4 · 4U 存储 | 4 | 24 块 3.5 英寸 SAS HDD；双控制器、中板、2 个风扇与双电源为演示内部配置 |

维护部件还包括上盖、处理器封装与散热器、托架与磁盘背板、导风罩、时钟电池、管理接口和线束。清单内的每一项都对应可选择几何；2U 计算设备有 21 个模块、36 个子件。GPU 等选配件在当前配置中明确未安装，不生成虚假槽位或遥测。1U/2U 计算设备保留已获准的贡献结构，并适配当前配置及原创补充部件；交换机与 4U 存储已接入保留贴图的贡献外观模型；展开时切换到独立制作的内部配置示意，复原后恢复外观。贡献资产不包含完整内部结构，示意配置不冒充其精确 CAD。通用配置不是某款厂商设备的精确 CAD 或维修手册。

形态与配置边界参照公开硬件资料：[1U 服务器与扩展槽](https://lenovopress.lenovo.com/lp1600-thinksystem-sr630-v3-server)、[1U 接入交换机](https://www.arista.com/en/products/7050x3-series)、[0U PDU](https://eshop.se.com/sg/apc-netshelter-basic-rack-pdu-0u-16a-208-230v-15-c13-outlets-ap9572.html)。这些是通用结构依据，没有使用其商标、图片、模型或源码；容量、端口分配和负载由本场景独立设定。

总览显示原始材质、必要状态标记与运行概览；开盖、展开和复原属于对象操作，在所有图层中可用。机房温度视图直接显示进风温度切片，可在图例中切换水平/垂直方向：水平调高度，垂直选 A/B 排并调离柜距离；标签分别显示“本层约”或“切面最高约”，U 位色条保留逐台设备读数。切换方向、位置或回看不改变对象和结构姿态。空白表示无有效估计，切片不代表整间机房环境温度。温度场景同时显示少量送风、穿柜与回风示意，路径随选择和机柜排变化；冷却输入与粒子共用模拟时钟，暂停及回看保持确定结果。路径颜色区分环节，送风线明暗表示冷却输入，均不代表实测风速或排风温度；停机或无效观测对象只保留静态示意。功耗通过预算标尺显示，设备内部保留部件表面着色。右侧只展示所选对象概览，温度取有效设备最高进风值，功耗仅汇总有效观测，分别报告覆盖率。运行、维护、停机、离线与数据质量独立记录；过期值停在最后观测，不进入当前合计，停机零功耗有效。部件温度与功耗是模型推导，不能充当独立测点或告警。

每台计算/存储设备有显式 A/B 接入关系，各接本柜一台交换机，端口唯一且速率匹配；没有虚构上联骨干或真实拓扑。每柜两个 24 插座 PDU 是结构附件，不重复计入整机功耗；上游电源独立性和 PDU 计量未定义。展开、镜头和运行时钟互不倒放。相同场景与时间产生相同结果，来源在 `src/simulation.ts`、`src/device-data.ts` 与 `src/spatial.ts`。

当前限制：维护部件已覆盖本轮明确的四种配置，不细分板上每个电子元件、紧固件或未安装选配件。交换机与存储的贡献模型主要表现外观，内部配置仍为参数化示意；尚无完整内部线缆与精确制造结构。数据、热场和分项功耗均为演示推导，没有 CFD、PUE 或真实管理接口。2U 贡献模型约 21 MB、1U 保留贴图模型约 20 MB，仍需压缩；远景按机型实例化，详细模型缓存限于四种配置。尚未进行性能基准测试。
