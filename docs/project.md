# 项目设计与路线

## 目标与当前状态

Mirage · 浮城是面向数据中心的三维数字孪生个人项目。目标是把现实基础设施的空间、结构、连接与运行变化组织为可探索的数字世界，同时积累三维图形、领域建模、模型流程、实时数据与性能工程经验。

面向希望理解机房及设备运行的体验者、开发者和运维人员。项目独立设计，不限定于某个厂商、某种设备或特定管理系统；服务器与超节点按各自结构处理。

当前已完成本地三维原型的机房、机柜与设备浏览链路，含室内与总览视角、旋转、缩放、选择、镜头聚焦、机柜铰链门与导轨抽出、9 个部件模组的可逆展开、28 个子件的独立选择与聚焦及明确标记的模拟状态。九段巡游串联开门、抽出、结构与归位，支持暂停、接管和循环；减少动态效果偏好下不自动巡游。已加入三机柜、六演示设备及共享时钟的温度、功耗和告警视图，以及冷却减弱、温度响应、告警升级和恢复的确定性模拟回放；三维提示绑定设备 ID，冷却关系明确标为预设示意。温度场、预算功耗占比和设备级告警直接绘制在模型表面，各机柜、设备与部件分别取值；机柜按最高进风温度、设备功耗之和及最高告警级别汇总。云图为预设温升与表面插值的演示模型，非实测或 CFD。趋势和事件按需展开，右侧展示概览；导航可搜索并折叠子件，子件采用显式节点映射与演示编号，展开跟随父模组。部件覆盖清单区分模型粒度与未知配置。运行方式及当前限制集中见 README。宏观入口、完整关系网络与真实数据接入尚未实现；下文保留后续目标。素材与许可集中见 [资产说明](../assets/README.md) 和 [许可范围](../LICENSE-ASSETS.md)。

## 体验范围

空间路径：**中国地图 → 园区 → 建筑 → 楼层 → 机房 → 机柜 → 设备 → 部件**。

| 方向 | 目标 |
| --- | --- |
| 空间浏览 | 园区分布、建筑分层、机房布局、墙体门窗、通道、制冷与配电设施；逐层进入、返回、旋转、缩放与聚焦 |
| 结构探索 | 机柜前后视角与开合、U 位安装、设备抽出/开盖、部件高亮、爆炸展开与复原 |
| 关系查看 | 网络端口与链路、供电与冷却关联、超节点成员；与物理位置联动 |
| 运行状态 | 功耗、温度、健康状态、指标趋势、告警发生与恢复；搜索和告警可直接定位 |
| 时间回放 | 场景暂停、重置、回看及重复运行，三维、拓扑和图表时间一致 |

中国地图使用前核实资源及适用要求，选材须符合项目的 CC0 规则；条件未满足时先使用明确标记的抽象园区分布入口，不把示意资源当作准确地图。

## 第一条完整链路

精做一个园区、一栋建筑、一个机房、一个机柜和一款可拆解服务器。先让空间浏览、设备选择和部件交互连续可用，再增加一个完整模拟场景：

**冷却能力变化 → 温度响应 → 告警触发 → 定位设备 → 查看趋势与关系 → 恢复回放。**

使用固定种子、有版本的场景与事件序列；其他对象用统一风格的原创简化资源。模拟规则和延迟明确记录，不宣称是精确热流体仿真或故障预测。超节点可作少量关系叠加或后续专题，不阻塞首条链路。

初期不连接实际管理系统，不执行远程开关机或配置变更。真实数据源从后续只读适配开始，单独记录验证范围。

## 领域设计原则

| 信息 | 基本约束 |
| --- | --- |
| 空间 | 明确坐标、单位、父级与稳定 ID |
| 资产 | 型号定义、安装实例与实际部件分开；槽位显式映射到模型节点 |
| 关系 | 网络、供电、冷却与成员关系分别建模，端点明确；不硬塞进单一空间树 |
| 状态 | 指标附单位、来源、观测时间与质量；健康、通信与告警分别记录 |
| 时间 | 所有视图共享时钟；模拟、实时与历史回放模式明确 |

设备既有机柜位置，也可有超节点成员身份；CDU 可关联多个机柜。关联不依赖显示名、数组顺序或猜测槽位，未知映射保持未知。

渲染层读取领域状态，模型通过映射关联业务 ID；选择、告警、搜索与拓扑共用对象标识。镜头动画不修改业务状态。模型姿态、部件配置信息和可逆爆炸编排按 [资产流程](../assets/README.md) 维护。

指标、告警与回放消费同一模拟状态，不让面板各自随机。相同输入和模拟时间得到一致结果；测量、模拟、派生汇总与推断明确标记。后续多源采集需定义更新、迟到和过期数据的合并规则。

功耗按设备、机柜和设施的计量边界汇总，标记覆盖率，区分转换损耗、未计量与缺失。零值有效，缺失、过期和离线分别表达。告警有稳定身份、严重度、对象及发生/恢复时间，考虑持续和恢复条件。相关异常不直接称为已证实根因。

## 渲染与技术选择

远景使用点位和简化几何，进入对应层级再加载细节。重复设备复用模型与材质，退出和取消加载时释放资源或使用有界缓存。示意与精确模型区分展示。

先验证桌面浏览器体验，再确定设备规模、画质与其他端适配。性能结果附设备、浏览器、对象规模、采样方法和限制；有原型后再制定可测预算。

原型采用 React + TypeScript + Vite，Three.js 负责参数化场景、射线选择与镜头控制。领域对象与层级状态、渲染对象和模拟时钟分离，使用稳定 ID 映射；重复静态几何按材质合并。场景定义与经维护者授权的原创贡献模型作为资产登记；GLB 部件通过显式节点契约关联 ID，加载失败有简化结构提示。使用局部面光源、细节接触阴影和程序化表面颗粒增强材质层次，保持标准渲染降级路径；阴影及后处理资源随引擎释放。渲染与交互代码为 Apache-2.0。地图方案、服务端与持久化尚未确定。

## 分阶段交付

| 阶段 | 交付目标 | 验收重点 |
| --- | --- | --- |
| 初始化（已完成） | 项目说明、资产与授权政策、隐私隔离及公开检查 | 公开文件无私有参考；许可全文完整；检查有效 |
| 原型验证 | 交互稿、最小应用、简化场景、模型与部件契约 | 可以启动，从机房进入机柜和设备；缺资源/失败有反馈 |
| 空间与结构 | 贯通宏观入口到部件的完整路径 | 返回与定位连贯；展开复原无累计误差；资源生命周期受控 |
| 状态与回放 | 一个有因果和恢复过程的模拟告警场景 | 重复运行一致；告警有依据；各视图时间相同 |
| 关系扩展 | 网络、供电、冷却、超节点及更多机型；只读数据适配 | 端点与映射清楚，双向定位一致，真实接入单独验证 |
| 作品交付 | 性能记录、公开演示、介绍视频与运行说明 | 他人可复现；资源许可可核对；成果与验证范围一致 |

当前下一步是细化已明确配置的部件和测点映射、模型压缩及细节分级，再扩展供电与网络关系。完整宏观路径仍需逐段建设。每完成一阶段，在此更新状态与验证入口；只有出现实际复杂度时再拆出专题文档。
