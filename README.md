## 项目介绍

浮城（Mirage）是一个面向数据中心的三维数字孪生个人项目。它规划以地球上的园区分布为入口，从园区、建筑与机房逐层深入机柜、设备和内部部件，将宏观的空间布局与微观的设备结构连接起来，构建一个可以浏览、探索和交互的数字世界。

项目规划通过机柜开合、设备抽出、结构拆解与爆炸图呈现设备形态，并结合网络、供电及冷却关系，关联功耗、温度、健康状态和告警等运行数据。借助空间定位与历史回放，让设备在哪里、如何连接、正在发生什么，都能在同一个场景中被观察和理解。

> 当前已实现本地的机房 → 机柜 → 设备 → 部件链路，包含双排八机柜、84 台混合设备、16 个后置 PDU 及演示供电端点。四种机型有独立的维护部件清单、可逆展开、选择与聚焦；温度、功耗、告警和态势共用一个可回放的确定性场景。宏观地图、完整关系网络与真机接入仍为建设目标，未部署在线演示。

## 探索路径

**地球 / 园区分布 → 园区 → 建筑 → 楼层 → 机房 → 机柜 → 设备 → 部件**

空间浏览、设备结构、网络/供电/冷却关系与运行数据相互关联。超节点作为可选的设备成员关系与专题视图，成员保留各自的物理位置。

第一版先贯通：**一个机房、八个混合机柜、四种设备配置、一个可重复播放的告警场景**。模拟数据明确标记，所有视图共享对象标识与时间线。先精修这套样板的场景表达、布局与设施关系，再扩展单园区，最后建设多园区与地球入口。详细边界与交付步骤见 [项目设计与路线](docs/project.md)。

## 当前运行与检查

原型使用 React、TypeScript、Vite 与 Three.js。建议 Node.js 24，最低 22.12；首次安装依赖后启动本地开发服务：

```bash
npm install
npm run dev
```

打开终端显示的本地地址，即可进入统一三维工作区。主入口为“总览 / 温度 / 功耗 / 告警”，对象操作和时间分析共用同一场景；默认从第 60 秒开始播放并自动巡游。顶部“演示”菜单可暂停或继续巡游，操作场景、查找资源或切换图层会接管为自由探索；模拟播放与巡游分别控制。减少动态效果偏好下默认自由探索，后台暂停画面、巡游与数据推进。

场景标签按任务收敛：总览只标所选对象，设备展开后随部件选择显示名称；“显示 → 更多对象标签”可补充浏览标记。选择用青白短角标；异常符号只在告警视图出现，总览、温度和功耗不叠状态符号或状态图例，设备内部不自动散布评估点。模型自带的铭牌和端口标识保留。对象详情先呈现状态、指标和小趋势，网络、供电与冷却关系以数量摘要按需展开；主动追踪对端时自动展开对应网络接入，完整配置与数据边界仍可查阅。

时间控制位于页头：播放/暂停按钮控制模拟，“分析”打开所选对象的完整曲线、共享时间与已发生事件，替换右侧普通详情。点击曲线、事件或使用方向键回看，镜头与开盖、展开姿态保持不变；分析栏顶部可返回详情。告警复用左侧资源筛选和场景标记，进入机柜后只查看该柜资源，不设置常驻底部告警表或时间条。场景与数据边界在“演示 → 场景与数据说明”中查看。

“演示”菜单可载入机房浏览、设备内部、告警排查和时间分析四个固定画面，载入时重置对象、时间、结构与切片设置并停止巡游。项目只保留一个正式工作区入口；旧评审、设计与原型链接不再触发特殊模式。后续页面调整遵循 [界面开发基线](docs/project.md#界面开发基线已确认)，功能范围与后续计划见 [工作区体验设计](docs/project.md#下一轮体验设计设计评审中)。

拖动旋转、滚轮缩放、单击选择、双击进入；面包屑与 Esc 返回，F 聚焦。机柜门与服务器导轨按顺序开合、抽出和归位；固定安装的交换机不使用抽屉动作，进入时切换到结构展示台。1U/2U 服务器可单独打开上盖观察装配内部，再展开或复原部件；合上上盖会先复原部件，返回机柜前自动合盖。手动开盖后“复原部件”保留开盖状态，图层和时间切换也保留结构姿态。设备支持独立部件选择。资源栏标题右侧可收起导航，从场景工具栏左端“资源”重新展开；搜索条件保留，窄屏按 Esc 关闭导航后焦点返回入口。左侧按柜排与设施分组，行右侧提供定位与进入，不再使用底部选中卡片；机柜内部保留 U 位，设备内部按实际机型显示模块与子件，支持搜索；小屏仍通过资源导航选择。自动建筑剖切、细节阴影与镜头环绕集中在“显示”。需要支持 WebGL 2 的桌面浏览器，小屏上下浏览场景与详情。

14×12 米机房有六个计算柜与两个计算/存储混合柜；交换机位于 U39 和 U41，4U 存储位于后排两柜的 U25–28 与 U35–38，PDU 装在后侧通道，不占标准 U 位。另有门禁读卡器、两处烟感、两处墙柱环境探头，以及制冷单元旁的漏水检测控制器和感应线，可从“环境与安全”资源组查找、选择与定位，详情显示配置位置、高度和数据边界；均未接入数据，不生成读数、事件或独立告警。两段既有桥架可从“建筑与布线”查找和定位，按需查看端点及下方机柜的空间对应；均为静态布置，没有运行数据或已接通线缆的含义。所有设备安装范围均做冲突检查；前置 1U 盲板按每柜实际安装 U 位独立生成，未安装位置连续封闭，数量与范围可在机柜“配置与数据说明”中查看。盲板不表示可分配容量。配置集中在 `assets/public/scenes/room-01.json`：

| 配置 | 数量 | 结构 |
| --- | --- | --- |
| M1 · 1U 计算 | 20 | 双处理器、8 条内存、4 个双转子风扇模组、4 块 SAS SSD、网卡、存储控制卡、单转接架与双电源 |
| M2 · 2U 计算 | 44 | 双处理器、16 条内存、4 个风扇、8 块 SAS SSD、网卡、存储控制卡、双转接架与双电源 |
| N1 · 1U 接入 | 16 | 48 个 25G SFP28、6 个 100G QSFP28、交换芯片、控制板、4 个风扇与双电源 |
| S4 · 4U 存储 | 4 | 24 块 3.5 英寸 SAS HDD；双控制器、中板、2 个风扇与双电源为演示内部配置 |

维护部件还包括上盖、处理器封装与散热器、托架与磁盘背板、导风罩、时钟电池、管理接口和线束。清单内的每一项都对应可选择几何；2U 计算设备有 21 个模块、36 个子件。GPU 等选配件在当前配置中明确未安装，不生成虚假槽位或遥测。1U/2U 计算设备保留已获准的贡献结构，并适配当前配置及原创补充部件；交换机与 4U 存储已接入保留贴图的贡献外观模型；展开时切换到独立制作的内部配置示意，复原后恢复外观。贡献资产不包含完整内部结构，示意配置不冒充其精确 CAD。通用配置不是某款厂商设备的精确 CAD 或维修手册。

形态与配置边界参照公开硬件资料：[1U 服务器与扩展槽](https://lenovopress.lenovo.com/lp1600-thinksystem-sr630-v3-server)、[1U 接入交换机](https://www.arista.com/en/products/7050x3-series)、[0U PDU](https://eshop.se.com/sg/apc-netshelter-basic-rack-pdu-0u-16a-208-230v-15-c13-outlets-ap9572.html)。这些是通用结构依据，没有使用其商标、图片、模型或源码；容量、端口分配和负载由本场景独立设定。

总览显示原始材质、选择标记与运行概览；开盖、展开和复原属于对象操作，在所有图层中可用。机房温度视图直接显示进风温度切片，可在图例中切换水平/垂直方向：水平调高度，垂直选 A/B 排并调离柜距离；标签分别显示“本层约”或“切面最高约”，U 位色条保留逐台设备读数。切换方向、位置或回看不改变对象和结构姿态。空白表示无有效估计，切片不代表整间机房环境温度。温度场景默认显示一条送风、穿柜与回风代表支路，路径随选择和机柜排变化；送风逻辑端点、柜前格栅、设备进风和回风假设就地标注，完整路径与边界可从图例展开；冷却输入与粒子共用模拟时钟，暂停及回看保持确定结果。路径颜色区分环节，送风线明暗表示冷却输入，均不代表实测风速或排风温度；停机或无效观测对象只保留静态示意。功耗通过预算标尺显示，设备内部保留部件表面着色。右侧只展示所选对象概览，温度取有效设备最高进风值，功耗仅汇总有效观测，分别报告覆盖率。运行、维护、停机、离线与数据质量独立记录；过期值停在最后观测，不进入当前合计，停机零功耗有效。部件温度与功耗是模型推导，不能充当独立测点或告警。

制冷单元详情可按配置查看 8 柜、84 台设备的关联范围、最高有效进风、覆盖率与设备告警；逐柜预览设备会切换当前代表气流。时间分析对照演示冷却输入（0–100%）和关联设备最高进风，共享回看与事件；恢复输入后仍可观察温度的滞后响应。输入百分比不是风量、制冷量或设施功率，关联进风不是制冷单元送/回风测点，关联事件也不等于已证实根因。过期、离线、缺失与停机无进风值分别说明，不进入当前最高值；部件沿用所属设备关系。

每台计算/存储设备有显式网络 A/B 接入关系，各接本柜一台交换机，共 136 条 25G 配置接入。总览对象详情支持逐柜查看接入交换机、按逻辑端口查找对端、显示未配置端口与端点标记；交换机登记 48 个 25G、6 个 100G 逻辑口，100G 尚未配置上联。服务器映射到网卡，存储按两控制器各一条接入，另外两口保持未配置；展开后的标记跟随所属部件。场景只标记当前一条关系的设备代表位置或内部部件，不是物理端口定位或施工线缆。链路状态、协商速率与流量未采集；未配置不等于空闲，设备离线不等于断链，A/B 不证明上联独立或冗余保障。没有虚构上联骨干或真实拓扑。

供电演示已定义配电柜的 16 个逻辑出线、16 个后置 24 插座 PDU 与 84 台设备的 168 个电源输入。功耗场景显示当前对象的代表配置支路，A 实线、B 分段，均为静态配线示意；右侧供电连接可追到已接/空闲插座和设备电源，并从已接插座或设备输入追踪单条配置支路；场景框选对应插座，切换视图收起标记，返回功耗或回看可继续。PDU 可搜索并定位到所属机柜后视，功耗或 PDU 观察会剖切后门与后立柱，离开观察后恢复；不是门板拆卸或实际控制。设备电源标签跟随部件展开，交换机与存储仍为内部配置示意。设施详情与时间分析只展示去重后的关联整机输入，保持有效覆盖，离线、过期、缺失与有效零值分开。配电柜、回路、PDU 和插座未计量，整机输入不拆分到 A/B，不据此声明独立上游或冗余保障。

展开、镜头和运行时钟互不倒放。相同场景与时间产生相同结果，来源在 `src/simulation.ts`、`src/device-data.ts` 与 `src/spatial.ts`。
