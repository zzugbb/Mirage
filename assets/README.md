# 模型与素材

当前 [资产清单](manifest.json) 登记了原创示意场景 [room-01.json](public/scenes/room-01.json)，以及经维护者确认授权纳入本项目的服务器、交换机、存储、制冷和供电柜体原创贡献模型。场景与模型均按 CC BY-NC 4.0 管理；其余外部选材仍只允许可核实的 CC0。

场景登记机房、机柜、不同机型的明确部件配置、U 位与接入关系；环境与安全设施另登记稳定身份、安装位置、承载墙面、定位视角与未接入数据标识，不从几何生成测点或告警。两处环境探头另由 `environmentMonitoring` 明确定义独立的确定性温湿度演示序列、采样间隔与质量窗口，仍未接入真实数据。检漏布置另登记控制器、引线、感应线和末端的配置路径，邻近设施关系不表示监测覆盖。桥架登记稳定身份、尺寸、承托结构、端点及柜排位置关系，不从布置对象推断施工连接或运行状态。入口门登记洞口、门框、门扇、五金、静态展示角度及门禁读卡器布置关系，独立参数化生成，不提供门状态或门锁控制。规模与硬件配置集中见 [README](../README.md)。1U/2U 计算设备使用已获准的贡献结构，并按当前配置适配维护部件；接入交换机与 4U 24盘存储使用贡献外观模型，内部配置、后置 PDU 和补充部件为自主参数化制作。1U 模型保留经维护者查看确认的原始贴图、材质与部件标识，并清理导出元数据；八条内存、四个双转子风扇模组和四个盘位分别可选。交换机与存储的风扇框体、开口、静态叶轮和拉取结构为独立参数化配置示意，仍沿用原部件身份；几何参数和定位方向集中登记，不声明真实叶型或风量。交换机与存储保留全部贴图与标识；外观资产没有完整内部节点，展开时切换为明确标注的内部配置示意，复原后恢复外观。存储按 4U 高度、24 个 LFF 盘位安装，不把原模型压成 2U。PDU 的局部位置、插座间距和电源部件映射已统一写入场景，模型与连接路径共用这些参数。网络逻辑端口范围、A/B 接入身份与网卡/控制器部件归属集中登记，场景标记默认使用设备代表位置。单条跳线样板在安装简模和贡献外观上定位到控制器区与接入口组，侧向折点为柜内布线示意。四种机型的安装简模后侧面板、接口区与通风格栅为独立参数化外观，尺寸和材质登记在场景中；只沿用整机选择身份，不声明物理端口映射、精确内部构造或实测散热能力。程序生成的布局与视觉参数集中在已登记的场景 JSON，生成算法为 Apache-2.0；原创视觉产物按资产许可管理。

单位为米，Y 轴向上，机柜正面朝 +Z。柜前格栅、地面开口与代表气流落点共用铺设配置，面框和横条齐平、下方为浅凹背衬。格栅按现有铺设网格派生两排布置身份，实例拾取与代表路径共用柜排对应；未增加模型文件，没有地下风腔、独占供风范围或独立测点含义。机柜尺寸与盲板宽度、厚度、接缝和固定点登记在场景中；封板范围逐柜由设备安装区间派生，柜门与顶部结构共同保持 42U 安装净空；双扇冲孔后门、顶部刷条进线口与 PDU 侧壁支架为自主参数化制作，尺寸集中配置。后门以外侧铰轴对开展示，角度和时长集中登记，关闭恢复原外廓；不声明真实门状态、工程开孔率或施工布线。模型定义与安装实例分开，安装高度按实际 U 数计算。原贡献节点与原创参数化部件分别声明映射，不用名称猜测未登记部件。子件保持装配矩阵、跟随所属模块展开；复原从绝对姿态计算。容量与已安装数量由配置明确指定，不从盘位网格数推断；没有据此生成独立实测遥测。

贡献模型已清理导出元数据与原始节点名称。贴图取舍按各资产审核结果执行：1U、交换机与存储保留已确认的标识和标签，其余已登记模型沿用此前的贴图清理版本。贡献作者按未署名原创贡献者记录，不将模型归称为维护者个人制作。原始本机来源与审核工作副本不进入公开目录。`scripts/prepare-model.mjs` 是清理工具，不自动判断权属或保密性；仍需人工审核实际纹理、几何与公开授权。

## 选材原则

园区、建筑、机房布局、机柜和关键设备以自主建模、参数化制作为主，保持统一尺度、材质和交互结构。简单环境对象直接制作，必要的外部素材只选来源可靠、可明确核实的 CC0；没有合适素材就自行制作简化版本。

不寻找授权不明、需要另行申请或附加其他使用条件的素材。此规则针对视觉素材，不替代正常软件依赖的许可要求。

本项目原创公开资产采用 CC BY-NC 4.0；外部 CC0 原作保持原状态，不改标原创或附加项目的非商用限制。技术文档、通用模式与清单仍为 Apache-2.0，完整范围见 [资产许可说明](../LICENSE-ASSETS.md)。

## 目录与版本维护

| 位置 | 内容 |
| --- | --- |
| `assets/public/` | 获准公开的模型、贴图、场景、预览及明确决定发布的源文件，正常提交和维护版本 |
| `assets/manifest.json` | 唯一的公开来源、许可与文件摘要清单 |
| `LICENSES/`（仓库根） | 标准许可全文，同一许可由多条记录复用 |
| `assets/source/`、`assets/restricted/` | 仍需保留的本机工作副本，忽略 |
| `assets/incoming/` | 待核实素材，忽略 |

公开子目录按实际需要建立，模型、贴图、场景和预览可分别组织。可公开母版，也可只公开运行时版本，由权利人决定；不要用文件格式或精度代替权属判断。

非公开资源可另在私有仓库或有版本的存储中维护源文件与备份，并在本地记录版本、摘要和存储位置。忽略目录不提供备份；当前未创建私有远端、搬运资产或完成备份。

## 制作与发布

1. 核实原创或 CC0 来源；工具生成、重新拼装、压缩或导出不自动带来原素材的授权。
2. 统一尺度、朝向和原点，运行时建议使用米；具体规范在原型中验证。
3. 区分模型定义、设备实例与部件实例，保留稳定 ID、槽位和节点映射；未知映射不猜测。
4. 记录装配姿态、爆炸偏移和复原姿态，制作按层级加载的细节版本。
5. 检查比例、材质、部件选择、展开复原、加载失败及资源释放；清理元数据中的私有信息。
6. 将拟发布版本放入 `assets/public/`，登记清单并运行公开检查；内容变化时同步更新摘要与映射版本。
7. 发布前核对模型、贴图、场景等依赖齐全，并包含对应许可；公开演示可独立于本机私有资料运行。

## 清单字段

顶层使用 `schemaVersion`、`defaultOriginalAssetLicense` 和 `assets`。每个实际文件填写：

| 字段 | 含义 |
| --- | --- |
| `id` / `path` | 稳定资源 ID，以及 `assets/public/` 内的文件路径 |
| `kind` | model / model-source / texture / scene / image / font / audio / video / map |
| `rightsHolder` / `source` | 原创主体或 CC0 提供方，以及简要公开来源 |
| `license` / `licenseFile` | 原创 CC-BY-NC-4.0 或外部 CC0-1.0，以及标准全文路径 |
| `sha256` | 当前发布文件的 SHA-256 |
| `publicationApproved` | 当前版本已经获准公开，必须为 true |

主模型及其贴图等依赖分别登记。公开场景 JSON 也属于资产；技术说明与许可文本不作为视觉资源登记。私有资源名称、地址与参考关系不放进此清单。

构建时可为已获准、摘要匹配的 GLB 生成 gzip 传输副本，解包后逐字节还原源文件，不改变资产许可或来源。源清单仍登记原始 GLB；构建清单在对应记录附加 `transport`：`encoding`、`path`、`sha256`、`byteLength`、`decodedByteLength` 与 `decodedSha256`，分别核对传输副本及还原内容。生成文件不回写源目录或源清单；原文件保留在构建包中供不支持原生解包的浏览器使用，许可文件随包保留。

来源集中记录，许可文本集中复用，不为每棵树或每个部件附一份重复说明。当前没有外部素材，不预建空的第三方许可副本。

检查脚本核对公开位置、许可标识、批准、摘要与私有信息，但不能替代人工确认权属，也不保证已经识别所有敏感内容。
