## 项目介绍

浮城（Mirage）是一个面向数据中心的三维数字孪生个人项目。它以地图为入口，从园区、建筑与机房逐层深入机柜、设备和内部部件，将宏观的空间布局与微观的设备结构连接起来，构建一个可以浏览、探索和交互的数字世界。

项目规划通过机柜开合、设备抽出、结构拆解与爆炸图呈现设备形态，并结合网络、供电及冷却关系，关联功耗、温度、健康状态和告警等运行数据。借助空间定位与历史回放，让设备在哪里、如何连接、正在发生什么，都能在同一个场景中被观察和理解。

> 当前已实现本地的机房 → 机柜 → 设备 → 部件链路，包含双排八机柜、84 台混合设备及后置 PDU。四种机型有独立的维护部件清单、可逆展开、选择与聚焦；温度、功耗、告警和态势共用一个可回放的确定性场景。宏观地图、完整关系网络与真机接入仍为建设目标，未部署在线演示。

## 探索路径

**中国地图 → 园区 → 建筑 → 楼层 → 机房 → 机柜 → 设备 → 部件**

空间浏览、设备结构、网络/供电/冷却关系与运行数据相互关联。超节点作为可选的设备成员关系与专题视图，成员保留各自的物理位置。

第一版先贯通：**一个机房、八个混合机柜、四种设备配置、一个可重复播放的告警场景**。模拟数据明确标记，所有视图共享对象标识与时间线。详细边界与交付步骤见 [项目设计与路线](docs/project.md)。

## 模型与素材

以自主建模和参数化搭建为主，必要外部素材只选来源可靠、可明确核实的 CC0。没有合适素材就自行制作简化版本，保持统一尺寸、材质和结构，不堆放不同来源的模型或重复许可文件。

获准公开的模型、贴图、场景、预览和源文件统一放在 `assets/public/`；来源与许可集中记录在 [资产清单](assets/manifest.json)。原创场景与经维护者授权的原创贡献模型均已登记；未引入 CC0 以外的第三方素材库资源。制作、导出和登记方式见 [资产说明](assets/README.md)。

## 当前运行与检查

原型使用 React、TypeScript、Vite 与 Three.js。建议 Node.js 24，最低 22.12；首次安装依赖后启动本地开发服务：

```bash
npm install
npm run dev
```

打开终端显示的本地地址。默认从机房总览进入运行态势并自动巡游，运行时钟从第 60 秒的混合状态开始。顶部可暂停或继续巡游；操作场景会接管为自由探索。场景角落的“趋势”按需打开温度、功耗或事件，展开“时间控制”后可暂停、拖动、调整 1/2/4 倍速及重播；关闭面板把空间交还给模型。数据来源集中在顶部“关于场景”，不在各面板反复标注。减少动态效果偏好下默认自由探索；后台暂停画面与巡游。

拖动旋转、滚轮缩放、单击选择、双击进入；面包屑与 Esc 返回，F 聚焦。机柜门与服务器导轨按顺序开合、抽出和归位；固定安装的交换机不使用抽屉动作，进入时切换到结构展示台。设备可展开、复原并选择独立部件。左侧按实际机型显示模块与子件，支持搜索；小屏通过结构页的下拉框选择。标签、接触阴影和环绕集中在“画面设置”。需要支持 WebGL 2 的桌面浏览器，小屏上下浏览场景与详情。

14×12 米机房有六个计算柜与两个计算/存储混合柜；交换机位于 U39 和 U41，PDU 装在后侧通道，不占标准 U 位。所有安装范围均做冲突检查。配置集中在 `assets/public/scenes/room-01.json`：

| 配置 | 数量 | 结构 |
| --- | --- | --- |
| M1 · 1U 计算 | 20 | 双处理器、8 条内存、4 个风扇、4 块 SAS SSD、网卡、存储控制卡、单转接架与双电源 |
| M2 · 2U 计算 | 44 | 双处理器、16 条内存、4 个风扇、8 块 SAS SSD、网卡、存储控制卡、双转接架与双电源 |
| N1 · 1U 接入 | 16 | 48 个 25G SFP28、6 个 100G QSFP28、交换芯片、控制板、4 个风扇与双电源 |
| S2 · 2U 存储 | 4 | 24 块 2.5 英寸 SAS HDD、双控制器、中板、2 个风扇与双电源 |

维护部件还包括上盖、处理器封装与散热器、托架与磁盘背板、导风罩、时钟电池、管理接口和线束。清单内的每一项都对应可选择几何；2U 计算设备有 21 个模块、36 个子件。GPU 等选配件在当前配置中明确未安装，不生成虚假槽位或遥测。新增结构为独立参数化建模；2U 计算设备保留已获准的贡献结构，并叠加原创补充部件。通用配置不是某款厂商设备的精确 CAD 或维修手册。

形态与配置边界参照公开硬件资料：[1U 服务器与扩展槽](https://lenovopress.lenovo.com/lp1600-thinksystem-sr630-v3-server)、[1U 接入交换机](https://www.arista.com/en/products/7050x3-series)、[2U24 双控制器存储](https://www.seagate.com/product-tours/data-storage-systems/exos-x-2u24/)、[0U PDU](https://eshop.se.com/sg/apc-netshelter-basic-rack-pdu-0u-16a-208-230v-15-c13-outlets-ap9572.html)。这些是通用结构依据，没有使用其商标、图片、模型或源码；容量、端口分配和负载由本场景独立设定。

“态势 / 结构 / 温度 / 功耗 / 告警”在中间工作区切换。态势采用局部指示条、定位标记与文字；温度和功耗按连续色阶叠加到设备表面。右侧只展示所选对象概览，温度取有效设备最高进风值，功耗仅汇总有效观测，分别报告覆盖率。运行、维护、停机、离线与数据质量独立记录；过期值停在最后观测，不进入当前合计，停机零功耗有效。部件温度与功耗是模型推导，不能充当独立测点或告警。

每台计算/存储设备有显式 A/B 接入关系，各接本柜一台交换机，端口唯一且速率匹配；没有虚构上联骨干或真实拓扑。每柜两个 24 插座 PDU 是结构附件，不重复计入整机功耗；上游电源独立性和 PDU 计量未定义。展开、镜头和运行时钟互不倒放。相同场景与时间产生相同结果，来源在 `src/simulation.ts`、`src/device-data.ts` 与 `src/spatial.ts`。

```bash
npm run build
npm run preview
npm test
```

公开内容检查仍使用 Node.js 内置模块：

```bash
node scripts/check-public.mjs
node --test scripts/check-public.test.mjs
git diff --check
```

当前限制：维护部件已覆盖本轮明确的四种配置，不细分板上每个电子元件、紧固件或未安装选配件。新增参数化设备保留通用外观，尚未制作制造级纹理与全部内部线缆。数据、热场和分项功耗均为演示推导，没有 CFD、PUE 或真实管理接口。2U 贡献模型约 21 MB，仍需压缩；远景按机型实例化，详细模型缓存限于四种配置。尚未进行性能基准测试。
